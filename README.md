# AudioEndpointSvc · 教室机摄像头占用监控

一个运行在 Windows 10 教室一体机上的极简监控小工具：记录摄像头被哪些应用、在什么时间、用了多久；在摄像头被占用时，于任务栏显示一个伪装成系统音频组件的小图标；托盘常驻同款图标，右键「进入主菜单」（口令保护）查看详细日志。

## 边界

- 只读取 Windows 的摄像头占用注册表（ConsentStore），**不打开摄像头、不采集画面/声音、不记录键盘、不联网**。
- 日志只存在本机程序目录 `logs/` 下。
- 伪装仅限于图标与名称这一层；不做进程隐藏、驱动级隐藏或对抗杀毒软件。
- 本工具面向**自己的或受托管理的机器**，用于设备使用管理与防误关。

## 功能

- 主菜单、登录、设置、日志查看均为内置 HTML 界面（系统自带 WebBrowser/IE11 内核，无需安装浏览器或额外运行时）。
- 摄像头占用实时检测（默认 1 秒轮询，CPU 占用≈0）。
- 记录：应用名、完整路径（UWP 为包族名）、PID、Windows 账户、开始/结束时间、时长、摄像头设备（单摄像头时精确归因，多摄像头时标注无法归因）。
- 全程只保留一个托盘图标（伪装为 Realtek 音频组件），右键菜单只有「进入主菜单」；主菜单需口令，内含筛选（时间范围、程序、设备）、按程序汇总（次数、总时长、平均、最长、最近一次）、导出 CSV、清理日志、修改口令，以及唯一的正常退出入口。
- 摄像头占用时可选择三种提示方式（设置里切换）：
  1. 在任务栏左侧应用区域新增一个伪装图标；
  2. 改变托盘图标（叠加红点，仍然只有一个托盘图标）；
  3. 在屏幕顶边常显传屏码浮层（深色圆角、白字“传屏码：XXXXXX”，每次启动随机生成 6 位码）；浮层吸顶，可沿顶边左右拖动，位置自动记住。
- 三种方式共用同一套显示条件：任何应用都提示 / 仅名单内应用提示 / 忽略名单内应用；条件只影响提示，**检测与日志始终全量记录**。
- 日志按天滚动为 `logs/YYYY-MM-DD.jsonl`，默认保留 90 天，自动清理。
- 单实例运行；程序目录下生成 `config.json` 与 `state.json`。

## 部署（教室一体机）

教室机 C 盘重启还原、D 盘不还原，因此：

1. 把 `AudioEndpointSvc.exe` 放到 D 盘（例如 `D:\AudioEndpointSvc\`）。
2. 由于还原机制，无法做开机自启：每次开机后手动运行一次。
3. 首次运行后，从托盘图标右键「进入主菜单」，按提示设置管理口令。
4. 日志与配置都在程序所在目录，随 D 盘持久保留。

> 程序不打开摄像头，不会与正在使用的视频软件冲突。

## 构建

本仓库使用 GitHub Actions 在 `windows-latest` 上构建（系统自带 .NET Framework 4.8 的 `csc.exe`，无外部依赖）。推送代码即触发 CI，产物为 `bin/AudioEndpointSvc.exe`（同时上传为构建产物）。HTML 界面以嵌入资源 `AudioEndpointSvc.ui.html` 打包进 exe，部署时仍然只有一个文件。

本地构建（可选）：

```powershell
./build.ps1
```

## 发布（自动）

CI 已配置两类自动发布：

- **最新构建**：每次推送到 `main`，都会更新 `build-latest` Release 里的 `AudioEndpointSvc.exe` 与 `manifest.json`，客户端据此自动更新；
- **版本化 Release**：推送 `v*` 标签时额外生成带版本号的 Release。

```bash
git tag v0.1.5
git push origin v0.1.5
```

## 自动更新

- 程序启动约 3 秒后在后台读取 `build-latest` Release 的 `manifest.json`（与 LDS/m-server 使用同一套机制），不阻塞界面。
- 网络层优先使用 WinHTTP（与 LDS/m-server 一致，支持系统代理与跨域重定向），失败时回退 .NET。
- 只有清单版本高于当前版本时才下载自己的 exe；下载依次尝试 `ghfast.top`、`gh-proxy.com`、`ghproxy.net`，最后才直连 GitHub。
- 下载完成后校验 SHA-256，写 `AudioEndpointSvc-new.exe`，由批处理在进程退出后替换当前 exe 并重启；日志与配置不受影响。
- 更新状态写入 exe 同目录的 `AudioEndpointSvc-update.txt`；每次源尝试的详细结果写入 `AudioEndpointSvc-update.log`，便于排查网络问题。
- 清单同时保留旧的 `camwatch` 键，改名前的旧客户端可借它迁移一次；如果旧客户端连旧清单地址都拉不到，需要手动安装一次 v0.1.8。
- 设置环境变量 `CLASS_NO_SELF_UPDATE=1` 可禁用自动更新（与 LDS/m-server 一致）。
- 更新需要 exe 所在目录可写；部署在 D 盘时满足。

## 配置项（config.json）

| 键 | 说明 | 默认 |
| --- | --- | --- |
| `displayMode` | 占用提示方式：`appbutton` / `tray` / `overlay` | `tray` |
| `overlayText` | 自定义吸顶浮层文字；留空则显示“传屏码：随机 6 位” | 空 |
| `overlayX` | 浮层上次拖动后的水平位置（像素）；缺省或 `-1` 表示默认靠右 | 无 |
| `taskbarMode` | 提示条件：`any` / `only` / `exclude` | `any` |
| `taskbarApps` | 条件名单：exe 文件名（如 `WeChat.exe`）或 UWP 包族名 | `[]` |
| `retentionDays` | 日志保留天数 | `90` |
| `pollMs` | 轮询间隔（毫秒） | `1000` |
| `disguiseName` | 伪装名称（托盘悬停显示） | `Realtek 高清晰音频管理器` |

口令以 PBKDF2（100000 次迭代 + 随机盐）保存，不存明文。

## 已知限制

- 多摄像头时无法精确归因到具体设备（Windows 的占用记录不提供设备维度）。
- Windows Hello 的红外摄像头走独立安全通道，不会被记录为普通应用占用。
- 若应用的摄像头进程异常崩溃，残留的“占用中”状态会被识别为进程已退出并收尾，不会误报持续占用。
- 方式 1 使用 APPWINDOW 隐形窗口，会同时出现在 Alt+Tab（标题与图标同为伪装名）。
- 方式 3 的传屏码为本地随机生成，仅用于视觉伪装，不参与实际传屏；浮层吸顶，只能沿屏幕顶边水平拖动（不能拖离顶边），拖动位置写入 `config.json`。
- 托盘图标可能被用户的任务栏设置收进 `^` 溢出区，应用无法通过受支持的 API 强制固定在音量/网络旁边。
- HTML 界面由系统 WebBrowser（IE11 内核）渲染，不支持最新的 CSS/JS 特性；若系统禁用 IE 内核，界面会提示资源加载失败。
- 学生若使用任务管理器仍可能发现进程——本工具不做对抗。
