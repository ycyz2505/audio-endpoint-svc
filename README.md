# camwatch · 教室机摄像头占用监控

一个运行在 Windows 10 教室一体机上的极简监控小工具：记录摄像头被哪些应用、在什么时间、用了多久；在摄像头被占用时，于任务栏显示一个伪装成系统音频组件的小图标；托盘常驻同款图标，右键「进入主菜单」（口令保护）查看详细日志。

## 边界

- 只读取 Windows 的摄像头占用注册表（ConsentStore），**不打开摄像头、不采集画面/声音、不记录键盘、不联网**。
- 日志只存在本机程序目录 `logs/` 下。
- 伪装仅限于图标与名称这一层；不做进程隐藏、驱动级隐藏或对抗杀毒软件。
- 本工具面向**自己的或受托管理的机器**，用于设备使用管理与防误关。

## 功能

- 摄像头占用实时检测（默认 1 秒轮询，CPU 占用≈0）。
- 记录：应用名、完整路径（UWP 为包族名）、PID、Windows 账户、开始/结束时间、时长、摄像头设备（单摄像头时精确归因，多摄像头时标注无法归因）。
- 任务栏伪装图标（仅占用时出现，释放即消失）：
  - 图标优先从本机已安装的 Realtek 音频程序提取，找不到时退回系统音量图标；
  - 显示规则可配置：任何应用都显示 / 仅名单内应用显示 / 忽略名单内应用；
  - 规则只影响图标显隐，**检测与日志始终全量记录**。
- 托盘伪装图标：右键菜单只有「进入主菜单」；主菜单需口令，内含筛选（时间范围、程序、设备）、按程序汇总（次数、总时长、平均、最长、最近一次）、导出 CSV、清理日志、修改口令，以及唯一的正常退出入口。
- 日志按天滚动为 `logs/YYYY-MM-DD.jsonl`，默认保留 90 天，自动清理。
- 单实例运行；程序目录下生成 `config.json` 与 `state.json`。

## 部署（教室一体机）

教室机 C 盘重启还原、D 盘不还原，因此：

1. 把 `camwatch.exe` 放到 D 盘（例如 `D:\camwatch\`）。
2. 由于还原机制，无法做开机自启：每次开机后手动运行一次。
3. 首次运行后，从托盘图标右键「进入主菜单」，按提示设置管理口令。
4. 日志与配置都在程序所在目录，随 D 盘持久保留。

> 程序不打开摄像头，不会与正在使用的视频软件冲突。

## 构建

本仓库使用 GitHub Actions 在 `windows-latest` 上构建（系统自带 .NET Framework 4.8 的 `csc.exe`，无外部依赖）。推送代码即触发 CI，产物为 `bin/camwatch.exe`（同时上传为构建产物）。

本地构建（可选）：

```powershell
./build.ps1
```

## 发布（自动）

CI 已配置为**自动发布**：推送一个 `v*` 标签到 `main` 分支即由 GitHub Actions 自动完成构建并创建 Release，无需手动执行 `gh release create`。

```bash
git tag v0.1.0
git push origin v0.1.0
```

生成的 Release 会自动附带 `camwatch.exe`。

## 配置项（config.json）

| 键 | 说明 | 默认 |
| --- | --- | --- |
| `taskbarMode` | `any` / `only` / `exclude` | `any` |
| `taskbarApps` | 名单：exe 文件名（如 `WeChat.exe`）或 UWP 包族名 | `[]` |
| `retentionDays` | 日志保留天数 | `90` |
| `pollMs` | 轮询间隔（毫秒） | `1000` |
| `disguiseName` | 伪装名称（任务栏/托盘悬停显示） | `Realtek 高清晰音频管理器` |

口令以 PBKDF2（100000 次迭代 + 随机盐）保存，不存明文。

## 已知限制

- 多摄像头时无法精确归因到具体设备（Windows 的占用记录不提供设备维度）。
- Windows Hello 的红外摄像头走独立安全通道，不会被记录为普通应用占用。
- 若应用的摄像头进程异常崩溃，残留的“占用中”状态会被识别为进程已退出并收尾，不会误报持续占用。
- 学生若使用任务管理器仍可能发现进程——本工具不做对抗。
